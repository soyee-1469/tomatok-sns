## 1. 컷 설계와 콘티

콘티는 구도뿐 아니라 연기 의도를 담는다. 컷별 고유 ID에 다음을 연결한다.

| 항목 | 기록할 내용 |
|---|---|
| 목적·상황 | 관객이 알거나 느껴야 할 것, 반응을 일으키는 사건 |
| 인물·공간 | 위치, 카메라 축, 이동, 화면 밖 상대 위치 |
| 샷·시선 | 샷 크기와 각도, 보는 대상과 화면 좌우 방향 |
| 감정 | 시작 → 계기 → 끝의 변화 |
| 표정·동작 | 눈썹·입·호흡·고개 등 관찰 가능한 행동 |
| 대사 연기 | 말하는 목적, 속도·강세·쉼·끝음 |
| 연속성 | 의상·소품·손·자세·앞뒤 컷 연결 |

- 대사마다 기계적으로 컷을 나누지 않는다. 행동과 감정이 이어지면 한 컷으로 합칠지 검토한다.
- 동일 이미지 반복은 연출상 이유가 있을 때 사용한다. 라이브러리에 있다는 이유만으로 재사용하지 않는다.
- 와이드=공간·동선, 미디엄·투샷=관계·행동, 클로즈업=중요한 감정. 모든 대사를 타이트 클로즈업으로 바꾸지 않는다.
- 콘티 번호와 현재 컷 번호가 같다는 이유로 연결하지 않는다. 인물·장소·행동·대사를 대조한다.
- 콘티 그리드·분할 방식은 검토 편의에 맞춘다. 스케치만으로 실제 눈동자·얼굴·영상 연기가 검증됐다고 하지 않는다.

## 2. 시작 스틸과 생성 전 검수

참조 역할을 분리한다: 콘티=구도·동선, 인물 원본=얼굴·의상, 세트 마스터=공간·소품, J4=선호하는 실사 질감·조명·자연스러움. 참조별 역할을 프롬프트에 명시한다.

- 샷 크기·각도·시선·시작 표정·행동을 짧고 구체적으로 작성한다. 클로즈업에 화면 밖 방 구조를 길게 넣지 않는다. 넓은 샷에 필요한 공간 정보는 남긴다.
- J4의 폰 불빛·85mm·정면 구도를 모든 장면에 강제하지 않는다. 조명과 시선은 해당 상황에 맞춘다.
- 얼굴 참조를 우선하며 다인 컷은 인물별 참조를 구분한다. 참조가 있다고 얼굴 일치를 보장하지 않는다.
- 얼굴 없는 콘티는 구도 참고로 사용한다. 얼굴 있는 콘티는 얼굴 참조와 섞이지 않도록 역할을 명시하고 결과를 대조한다.
- 영상이 이어받을 행동의 시작 순간을 만든다. 표정이 이미 과장되거나 무표정인 스틸을 그대로 넘기지 않는다.

영상 생성 전 원본 얼굴과 나란히 놓고 확인한다.

1. 얼굴·머리·안경·의상 일치, 양쪽 눈 정렬과 눈동자 방향.
2. 손·손가락·소품·신체의 물리적 이상 여부.
3. 인물 위치·가구·카메라 축·소품의 앞뒤 연속성.
4. 장면 시작 감정과 시선 대상의 적합성.
5. 넓은 샷도 얼굴을 확대해 확인. 작아서 판단할 수 없으면 ‘검증 불가’로 표시하고 구도 조정 또는 별도 1컷 검증 대상으로 둔다.

틀린 얼굴·시선·눈·손을 영상 모델이 고쳐줄 것으로 기대하지 않는다. 얼굴 점수와 픽셀 폭은 보조 정보다. 과거 점수 0.45·얼굴 폭 기준을 통과해도 동일 인물이나 자연스러운 연기를 보장하지 않는다. 페이스스왑·GFPGAN으로 승인 없이 인물을 바꾸지 않는다.

스틸 승인 전에는 [현행 상세 QA 12항목](references/frame-qa.md)을 모두 확인하고 항목별 통과/보류/해당 없음을 기록한다. 위 5항목은 요약이며 검사 범위를 줄인 것이 아니다. 과거 250px·0.45는 경고와 비교 근거로 유지한다. 미달·측정 불가를 무시하지 말고 원본 대조와 별도 검증을 하되, 수치 하나로 좋은 장면을 일괄 폐기하지 않는다.

## 3. 음성·연기와 시간 설계

인물의 기본 음색과 컷별 말투를 분리한다. 낮고 차분한 음색이라도 모든 문장을 끝음 내림으로 만들지 않는다. 리아·수만 언어는 최신 `bea_language_rule.md`, `suman_language_rule.md`와 각본을 확인한다. 한국어·영어·네팔어를 일괄적으로 ‘native Korean only’로 덮어쓰지 않는다.

- 대사 원문에는 `(감정, 말투, 강세·쉼, 끝음↑/↓/유지)`를 기록한다. 화면 자막은 발화 글자만 표시하고 연기 지시를 넣지 않는다.
- 발화 전: 무엇을 보고 왜 멈추는가.
- 발화 중: 어떤 목적과 감정으로 어떤 단어를 강조하는가.
- 발화 후: 상대에게 무엇을 기대하며 어떻게 반응하는가.
- ‘당황·코믹’만 쓰지 말고 눈썹·시선·호흡 등 읽히는 행동을 적는다.
- ‘무표정’, ‘표정 최소’, ‘입만 움직이기’, ‘고개·몸 정지’, ‘항상 끝음 내림’을 공통 기본값으로 넣지 않는다.
- 과장을 막을 때는 이 컷에서 피할 구체적인 행동만 적는다. 자연스러운 호흡·작은 고개 움직임·시선 변화를 허용한다.
- 읽어보기 또는 임시 음성으로 발화 길이를 확인한다. 대기·발화·반응을 합쳐 모델 지원 길이 안에서 컷 시간을 결정한다. 3초에 긴 대사를 밀어 넣지 않는다.
- 중요한 타이밍은 편집으로 조정하되, 보이는 입과 음성을 임의로 어긋나게 하지 않는다.
- 임시 음성 승인은 영상 모델에 그 음성을 적용할 수 있다는 뜻이 아니다. 오디오 입력·립싱크 지원과 비용은 별도 검증한다.

시간 지시 예시(4초는 예시이며 실제 대사에 맞춰 조정):

```text
0.0–0.7s: 폰을 읽고 짧게 숨을 들이쉰다. 말하지 않는다.
0.7–1.1s: 상대에게 시선을 옮기며 눈썹이 조금 올라간다.
1.1–2.1s: “제가요?” ‘제가’에 약한 강세, 조심스럽게 묻는 끝음 올림.
2.1–4.0s: 입을 자연스럽게 닫고 답을 기다린다.
```

## 4. 애니매틱과 장면별 확정

- 흐름·이해도·중복 샷·시선·동선·발화 속도·쉼·웃음과 반응 시간을 검토한다.
- 애니매틱 통과는 흐름 승인이다. 생성 영상의 얼굴·연기·립싱크 승인이 아니다.
- 전체 각본은 반복 수정할 수 있다. 이번 유료 생성 장면의 대사·연기·시작 스틸 버전을 먼저 고정한다.
- 승인 후 변경이 생기면 영향받은 컷만 재검토한다. 이미 승인된 다른 장면을 전부 무효화하지 않는다.

J4+11-06은 선호 기준이지 모든 컷의 구도나 성공 보장이 아니다. 기존 `gen_kling_lines.py`가 이 기준을 반영했는지 실행 전에 실제 코드와 제출 프롬프트를 확인한다. 백업 복원으로 이후 수정사항을 무조건 덮어쓰지 않는다.

- 일반 대사 컷: 시작 이미지 중심. 같은 이미지를 끝 이미지로 잠그는 것을 기본값으로 사용하지 않는다.
- 도착 위치가 중요한 이동 컷: 시작·끝 이미지 사용을 별도 검토한다. 시작·끝의 축·인물·세트·소품을 대조한다.
- 고정 샷이면 단일 샷·컷 없음·줌/팬 없음·좌우 반전 없음으로 카메라를 지시한다. 인물까지 정지시키지 않는다. 계획된 카메라 이동은 별도 시험한다.
- 대기 → 반응 → 발화 → 발화 후 반응을 시간대로 지시한다. 화면 밖 공간·인물은 방향 이해에 필요한 최소 정보만 넣는다.
- 대사 컷은 기본적으로 한 번에 한 화자. 손·소품 행동이 핵심이면 보이는 동작 하나를 명확히 지시하고 복잡한 동시 행동은 분리한다.
- 차임·진동·음악·자막·UI는 필요 시 후합성한다. 생성 대사에 효과음 지시나 글자가 섞이지 않게 한다. 기본 생성 영상에는 음악 없음.
- 과거 Kling 3.0 std 표본 설정은 720×1280, cfg_scale 0.5, enhance_prompt off, sound on. 현재 지원 여부·길이·비용을 조회하며 자동으로 pro/고해상도로 올리지 않는다.
- 시간·얼굴·말투는 프롬프트로 보장되지 않는다. 중간·끝의 얼굴 변화는 실제 생성 후 확인한다.

## 6. 시험 생성·수정 관리

잘 나온 원본의 시작 이미지·참조·전체 프롬프트·모델·실제 적용 설정·길이·결과·판정·비용을 한 세트로 보존한다. 모델이 지원하면 seed도 기록하되 재현성을 보장하지 않는다.

```text
기준 채택본 / 회차·컷 ID / 각본·스틸 버전:
이번 변경:
유지할 요소:
채택 기준:
장수·길이·단가·총비용:
실패 시 대안:
```

- 새 방식은 완성본에 사용할 대표 1컷으로 시험한다. 사용자 확인 전 2컷 이상 동시 생성하지 않는다.
- 가능한 한 변수 하나만 바꾸고 실제 제출 프롬프트·설정 차이를 확인한다.
- 대사 톤만 수정할 때 이미지·시선·동작·감정 변화·카메라·발화 시점까지 임의로 바꾸지 않는다.
- 음성 수정으로 영상 전체를 재생성하면 기존 연기도 바뀔 수 있음을 알린다. 수정본과 채택본을 나란히 비교하고 좋아졌을 때만 교체한다.
- 클로즈업 성공을 미디엄·와이드·다인·이동 컷 성공으로 확대하지 않는다. 새 유형은 별도 검증한다.
- 원본 채택본은 덮어쓰거나 삭제하지 않는다. 요청 타임아웃 등 제출 여부가 불명확하면 작업 ID·상태를 먼저 확인하고 중복 제출하지 않는다.

## 7. 생성 후 검수·중단 조건

전체 재생과 앞·중간·끝 프레임을 확인한다. 짧게 잘라 쓸 수 있으면 사용 구간을 기록한다.

| 기술 검수 | 사용자 연기 검수 |
|---|---|
| 얼굴·눈·손·소품 변화 | 감정과 인물 의도가 읽히는가 |
| 시선·축·카메라·내부 컷 | 무표정·과장·부자연스러움 여부 |
| 대사 누락·변형·언어·립싱크 | 속도·강세·끝음·쉼 |
| 음량·파일·해상도 | 상대에게 말하고 듣는 느낌 |

자동 점수·whisper 통과를 ‘연기 승인’으로 보고하지 않는다. 사용자가 연기 불채택한 영상을 자동 QA 때문에 채택하지 않는다.

- 실패 원인을 기록하지 못하면 같은 요청을 반복하지 않는다.
- 기존 비용 규칙 유지: 최초 1회 + 원인을 고친 재시도 1회. 세 번째는 별도 사용자 승인.
- 두 번 실패하면 자동 재생성을 중단하고 샷 분리·편집·화면 밖 대사·기존 자료 등 대안을 제시한다. 모든 실패를 플레이트 전체 재생성으로 해결하지 않는다.
- 사용자 대표 결과 승인 후 작은 배치로 확대한다. 배치마다 검수·가편집에 반영해 완성본에서 효과를 확인한다.

## 8. 비용·완성 관리

- 생성 전 현재 비용을 조회해 장수×단가·길이·총액을 보고하고 승인을 받는다. 이 문서 수정 자체는 생성 승인이 아니다. 이미 승인된 명확한 범위·한도는 중복 승인받지 않는다.
- 기존 승인 한도 유지: 세션 40cr, 에피소드 300cr. 초과 전 누적 사용량·남은 작업·예상 비용을 보고하고 승인을 받는다.
- 권장 시험 범위는 스틸 최대 1장+영상 1컷. 사용할 스틸이 있으면 새로 만들지 않는다. 시험도 실제 편집에 쓸 컷으로 한다.
- 과거 2cr/스틸·6cr/3초, 무제한 프로모션·갱신일을 현재 사실로 단정하지 않는다. 실제 계정·모델·기간·조건을 확인한다.
- 영상 12컷 안팎은 절약을 위한 계획 참고값이다. 대사 전부를 영상화하거나 모든 반응을 스틸로 고정하지 말고 연출상 필요와 예산으로 선택한다.
- 라이브러리는 감정·시선·행동·연속성이 맞을 때 사용한다. 대사만 바꾼 반복 화면을 양산하지 않는다.
- 립싱크 오류를 자막으로 해결됐다고 판정하지 않는다. 음성이 맞는 화면 밖 대사·인서트 등 대체 편집을 검토한다.
- 새 결제·유료 패스·새 모델 탐색을 반복 실패의 기본 해결책으로 삼지 않는다.
- 생성별 상태표에 비용·누계·채택 여부·실패 원인·사용 구간을 기록한다. 생성 완료 수보다 편집에 반영된 채택 컷과 남은 부족 컷을 보고한다.

## 9. 분담·보드·인수인계

- 사용자 지정 분담(2026-11-13 “니가 리더를 하고 클로드랑 커서를 시킬께”)을 따른다.
- 코덱스: 총괄, 변경 범위·비용·판정 관리와 통합.
- 클로드: 각본·컷 구성·연기 지시와 수정.
- 커서: 보드·생성 도구·렌더·검수·편집 자동화. 별도 지시 없는 유료 생성 금지, 도구 확인은 dry-run.
- 사용자: 비교 자료를 보고 연출·연기를 채택한다.
- 이 분담은 외부 AI 자동 호출 기능이 있다는 뜻이 아니다. 실제 연결 여부를 확인하고 미연결이면 작업 지시서를 제공한다. 기존 커서 운영 규칙은 `tools/CURSOR_TASKS.md`를 5분 주기로 읽고 `## 처리 보고`에 결과를 남기는 방식이다. 이 규칙은 유지한다. 실제 커서 세션·폴링이 실행 중인지 확인하고, 미실행 상태에서 전달 완료나 자동 실행을 주장하지 않는다.
- 반복 도구 작업은 `tools/CURSOR_TASKS.md`에 목적·입출력·허용 파일·검증·생성 금지를 명시한다.
- 보드 한 곳에서 컷 ID별 각본·콘티·스틸·프롬프트·영상·판정을 연결하고 현재본/대안/추천 이유/변경 영향/비용을 보여준다.
- 작업자가 해결할 버전 동기화·명백한 기록 충돌은 먼저 정리한다. 사용자에게 파일명만 나열해 선택을 요구하지 않는다. 실제 이미지·영상과 앞뒤 맥락을 제공한다.
- 파일 변경 뒤 관련 상태를 갱신한다. 승인 원본·에셋을 보존하고 변경 파일·검증·남은 불확실성을 보고한다.

## 10. 도구와 아직 검증되지 않은 경로

비용 조회·스틸/영상 생성·전사·마무리·아웃트로·최종본 명령은 [현행 운영 명령어](references/operations.md)를 따른다. 유료 생성·최종본 교체 전 해당 승인 범위를 확인한다.

- 생성 도구: `01_EPISODES/EP01R/tools/hf_gen.py` (EP01에도 사본 있음). 실패·참조 이미지를 결과로 오인하지 않도록 실제 작업 상태와 결과 URL을 확인한다.
- 음성 전사: `01_EPISODES/EP01/tools/transcribe.py` 또는 회차별 사본. 언어·짧은 외국어는 직접 청취도 필요하다.
- 보조 검수: `tools/face_score.py`, `tools/clip_qa.py`, `tools/face_qa.py`.
- 콘티: `tools/split_storyboard.py`, `tools/make_storyboard_prompts.py`.
- 보드: `tools/build_series_board.py`, `tools/series_board.html`, `tools/serve_series_board.py`; 검토 기록 `tools/series_board_reviews.json`은 보드 재생성과 독립 보존.
- 합성·조립·자막·오디오 도구는 해당 회차의 실제 파일과 인수인계에서 확인한다. 현재 선택된 클립 목록으로 렌더하고 자막은 확정 대사와 대조한다.
- 최종 편집에서 앞뒤 연결·소리·자막·화면 안전 영역을 전체 재생으로 확인한다. 승인된 최종본도 이번 수정 범위 밖에서 덮어쓰지 않는다.
- 미검증: 넓은 샷의 얼굴 유지, 한국어 말투 재현성, 기존 연기를 보존하면서 음성만 수정하는 경로와 비용. 모델·계정별 지원을 확인하고 필요한 경우 1컷 시험 전까지 ‘해결됨’으로 기록하지 않는다.

## 11. 최종본 보관과 변경 취지

- `99_FINAL/EPnn_제목_FINAL.mp4`는 에피소드당 한 파일만 유지한다. 작업 버전과 과거 채택본은 회차의 edit/export/video에 보존한다. 사용자가 최종 교체를 요청하거나 승인한 경우에만 같은 최종 파일을 교체하고 `99_FINAL/README.md` 참조도 갱신한다. 구본을 먼저 삭제하지 않는다.
- 길이 규칙 변경은 의도적이다: 짧은 대사 컷을 우선하되 3초 상한·5초 일괄 금지를 폐지한다. 실제 발화·쉼·반응과 비용으로 길이를 정하고 긴 컷은 별도 검증한다.
- 얼굴 수치는 합격 보증이나 유일한 폐기 기준이 아니다. 경고 시 눈으로 검증하는 절차는 강화한다. 상세 QA 항목은 생략하지 않는다.
